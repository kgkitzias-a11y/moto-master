# DECISIONS.md — Moto Master

Every decision taken autonomously during the build, in order. Format: **D-nnn (date) — decision** → why.

- **D-001 (2026-09-14) — Photos are never modified.** All rotation/splitting/upscaling happens on copies under `work/pages/` (git-ignored). The `question pictures/` folder is git-ignored and only read.
- **D-002 (2026-09-14) — Photo orientation map.** photo01 upright single page; photo07 rotated 180°; photos 02,03,04,09–16 rotated 270°; photos 05,06,08,17,18,19 rotated 90° (PIL `rotate`, CCW). Each spread is split at 45 %/55 % with overlap into `_L`/`_R` half pages, upscaled 2× (LANCZOS), autocontrast + sharpen for transcription.
- **D-003 (2026-09-14) — Transcription protocol.** Two independent vision passes (A/B) per half page by separate subagents, a script diffs them, a third pass re-reads the photo for every discrepancy. The answer-key table gets the same A/B/resolve treatment.
- **D-004 (2026-09-14) — GitHub CLI installed with winget (user scope)** to `%LOCALAPPDATA%\Microsoft\WinGet\Packages\GitHub.cli_…\bin\gh.exe`; device login was started immediately (Phase 4 prerequisite) so the wait overlaps with the build.
- **D-005 (2026-09-14) — Booklet has 140 questions, not 139.** The answer-key table prints exactly 140 ids (32 absent: 4, 13, 14, 18, 22, 28, 39, 40, 43, 64, 79, 84, 93, 99, 101, 122, 125, 126, 130, 131, 137, 143, 146, 147, 148, 155, 156, 159, 162, 163, 166, 167) and the same 140 ids are physically present on the pages. The spec's "~139" was an estimate; the booklet is ground truth. Mode ids stay `gauntlet139`/`gauntlet172` for the spec's names, but the UI labels use the real counts ("Gauntlet βιβλίου (140)").
- **D-006 (2026-09-14) — Exam format: 10 questions, max 1 wrong, 10-minute timer.** Official text (ΥΑ 50984/7947/2013 Β' 3056, άρθ. 22 as replaced by ΥΑ Δ30/Α3/71830/2024 Β' 1737; unchanged in the 2025 codification): Ερωτηματολόγιο 2 (μοτοσικλέτες) = 10 questions, pass with ≤1 wrong, **15 minutes**. The school's 10 questions / ≤1 wrong matches; the school's 10 minutes is stricter than the official 15, and the spec says "use the official format if stricter" → keep the stricter 10-minute timer. Holding B (code 121) only exempts Ερωτηματολόγιο 1; Ερωτ. 2 is still examined on the ΜΣΘΕΥΟ computer system with per-candidate random questionnaires and possibly re-ordered options (hence option shuffling in every mode). Source report: `work/research/exam_format.md` (git-ignored) summarised in AUDIT.md.
- **D-007 (2026-09-14) — Old app dataset is an independent cross-check, not a source.** https://moto-master-gr.dinos94.chatgpt.site/ embeds 172 questions (139 active / 33 inactive) in its JS bundle; zero correct-answer disagreements with the booklet key on the 140 shared ids; 13 wording differences, all resolved by re-reading the photo (booklet wins). Its category labels and template "rationale" were NOT reused.
- **D-008 (2026-09-14) — No question in the booklet has a picture.** All 19 photos were transcribed twice; `has_image` is false for every question, so no crops were needed and "Μόνο πινακίδες" (Signs Only) is present but empty (the card explains why). If an archive question gains an image later, the mode activates automatically.
- **D-009 (2026-09-14) — Printed misspellings are kept verbatim** ("τρόχο" in Q48 γ, "πράγματά" in Q170 γ, "Μια" without tonos, "180°" for the superscript-zero glyph in Q95 as the only normalisation). Exact wording is the contract; deviations are listed in AUDIT.md.
- **D-010 (2026-09-14) — Storage: IndexedDB event log, localStorage for settings and token.** Events are short-key JSON objects `{id,t,k,q,ch,ok,ms,m,s,cf,sh,tl,hd,rc}`; the reducer sorts by (t,id) so union of two logs is order-independent. The token lives under its own localStorage key (`mm.gh.token`) and is never included in exports, settings, logs or URLs (except the deliberate pairing URL the user generates).
- **D-011 (2026-09-14) — Reset is an event.** "Μηδενισμός" appends a `reset` marker; the reducer ignores everything at or before it, and sync compacts older events away, so a reset propagates to every device instead of resurrecting from the gist.
- **D-012 (2026-09-14) — Mastery rules, stricter readings chosen:** (a) level 5 additionally requires the promotions to span ≥3 distinct local days (8 h gaps alone allow 2 days); (b) promotion time limit = 15 s per question (`PROMOTION_TIME_LIMIT_MS`), Speed Round's 5 s applies when stricter; (c) "solid" median is over ALL recorded response times of the question, timeouts included; (d) Recall self-grades count for seen/accuracy and can demote/bin, but never promote or count toward bin exit (options were not shuffled); (e) the confidence choice must be made before the options unlock and the response clock runs from question display, so hesitation costs time; (f) a wrong answer while already in the bin restarts the 3-day exit count; (g) wrong while "Σίγουρος" or in Hard Mode → level 0 and the promotion-day history is wiped.
- **D-013 (2026-09-14) — Token type: classic PAT with only the `gist` scope.** GitHub's fine-grained PAT docs list only write endpoints under the "Gists" permission (POST/PATCH/DELETE) and no GET /gists (list) — the find-or-create flow needs the list endpoint and secret-gist reads, so fine-grained tokens are not documented to work. Verified on docs.github.com on 2026-09-14 (`permissions-required-for-fine-grained-personal-access-tokens`).
- **D-014 (2026-09-14) — Sync race window accepted.** Two devices PATCHing the same gist within seconds can overwrite each other; every push carries the full union and every device re-adds anything the remote lacks on its next sync, so the logs converge (eventual consistency) — no data is lost permanently, only delayed. No last-write-wins anywhere.
- **D-015 (2026-09-14) — Pairing QR encodes a URL** (`https://…/moto-master/#pair=<base64url{token,gistId}>`). Because Safari and the installed iOS app do not share storage, the installed app also offers an in-app camera scanner (vendored jsQR) and a paste field, so pairing can be completed inside the home-screen app. The README says to install first, then pair inside the app.
- **D-016 (2026-09-14) — Vendored, no CDN:** qrcode-generator 2.0.4 (MIT) and jsQR 1.4.0 (Apache-2.0) under `src/vendor/` with licences.
- **D-017 (2026-09-14) — Response clock starts at display time.** `Session.show(now)` is called by the UI when a question is rendered; the per-question deadline and `ms` are measured from there, not from the previous answer (code-review finding #1: Speed Round would otherwise auto-fail questions while the user read the previous feedback).
- **D-018 (2026-09-14) — Untrusted events are sanitised.** Everything pulled from the gist or imported from JSON passes `src/engine/events.js` (UUID id, known kind, whitelisted keys, typed fields, timestamp within [2020-01-01, now+24 h]) — a far-future `reset` in a crafted file can no longer wipe the log. Locally generated events are trusted.
- **D-019 (2026-09-14) — Canonical serialisation.** Exports and the gist file use sorted-key, whitespace-free JSON so equal logs are byte-equal on every device (the e2e byte-equality checks depend on it).
- **D-020 (2026-09-14) — Pairing QR is not a URL.** The QR encodes `mm1:<base64url>` so the iOS Camera does not open Safari (whose storage the installed app cannot see) and the secret never lands in URL history; the in-app scanner and the paste field accept it, and `#pair=` links still work but ask for confirmation when a different token already exists. Pre-reset events are also pruned from the local log at sync time so they are never re-pushed (review finding #5).
- **D-021 (2026-09-14) — CSP via `<meta>`:** `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; connect-src 'self' https://api.github.com https://gist.githubusercontent.com; …`. The raw_url host is validated against `gist.githubusercontent.com` and the token is not sent to it (secret raw URLs are unguessable and public).
- **D-022 (2026-09-14) — The 13 PDF-only questions are NOT shipped.** The spec's "≥2 independent sources" rule is applied literally; the old app is a scrape of the same PDF and does not count. Their text is preserved under `work/recovery/` for a future owner decision.
- **D-023 (2026-09-14) — Lighthouse has no PWA category any more (v12+).** Installability is verified by the Playwright `pwa.spec.js` (manifest fields, icons, SW registration) and by loading the live URL; the remaining Lighthouse categories are recorded in README.
